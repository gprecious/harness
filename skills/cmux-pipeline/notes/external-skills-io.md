> `~/.claude/skills/office-hours/SKILL.md` (flatten 본) 를 인용한다.

### 출력 파일 (문서 기반, verified=NO)

**`/office-hours` 의 메인 산출물 = design doc 1 개.**

- 출처: `~/.claude/skills/office-hours/SKILL.md:1531-1546`

## build-loop (참고용 — 외부 호출 안 함)

cmux-pipeline 은 build-loop 를 *외부에서 invoke 하지 않는다*. Task 1 의 결정에 따라
build-loop 의 5-phase dispatcher 패턴(Assess → Plan → Execute → Review → Iterate, +Learn)
을 직접 차용하여 우리 `stage-loop.sh` 가 그 역할을 수행한다.

설치된 layout (참고):
- commands: `~/.claude/plugins/...` 안에 14개 (`assess.md`, `plan-verify.md`, `run.md`,
  `optimize.md`, `debug.md`, `research.md`, `start-prd.md`, `test.md`, …)
- agents: 20개 (`build-orchestrator.md`, `assessment-orchestrator.md`, `implementer.md`,
  `plan-critic.md`, `fact-checker.md`, `root-cause-investigator.md`,
  `recurring-pattern-detector.md`, …)
- MCP server `build-loop-debugger` 자동 등록 (`.mcp.json` 통해; incident-memory 도구 제공)

build-loop 는 `~/.build-loop/` 같은 글로벌 state 가 있을 가능성이 있으나 — cmux-pipeline 이
의존하지 않으므로 본 task 범위 외.
